# Issue Graph — план работ (roadmap)

На основе [AUDIT.md](./AUDIT.md). Цель: сделать инструмент юзабельным на реальных
данных (сотни слабосвязанных задач в нескольких проектах), затем — расширить до
«не выходя в GitLab» и Kanban-доски.

Порядок этапов = порядок ценности/риска. Этапы 0→2 закрывают «нечитаемо», 3→4 —
«медленно», 5 — навигацию, 6 — паритет, 7 — инструменты, 8 — Kanban.

Принцип очередности (из ревизии): **первой чинить раскладку/вид, а не бэкенд** —
дёшево, мгновенно, без зависимости от GitLab. Ускоренный бэкенд без фикса
раскладки просто быстрее покажет ту же полосу.

---

## Подтверждённые продуктовые решения

- **D1. Закрытые задачи скрыты по умолчанию.** Грузить `state=opened` на бэке
  (вместо хардкода `state=all` в `graph.py:61-64`) → меньше N+1 и меньше нод на
  холсте. Видимый тумблер «открытые / все» (уже есть `App.tsx:947`) догружает
  closed. Счётчик с подписью «120 открытых / 470 всего» делает скрытие прозрачным.
  Нюанс: связи к незагруженным closed-задачам не строятся (компромисс приемлем).
- **D2. Скрытие по возрасту — НЕ молчаливый дефолт.** Если объёма всё ещё много —
  добавить пресет «активные за N дней» **только по `updated_at`** (не `created_at`
  и не `due_date` — иначе скроется долгоживущий бэклог / задачи без срока) и
  **только как видимую плашку** «Показаны задачи, активные за 30 дней (123 из 470)
  · показать все». Не включать агрессивно по умолчанию: сначала смотрим, хватает
  ли D1.
- **D3. Новая карточка — Вариант 2 (появляется там, куда смотришь).** После
  создания ставить ноду в **центр текущего вьюпорта** (`screenToFlowPosition`),
  закреплять позицию в `pinnedRef` (механизм уже есть `App.tsx:175-191`), выделять
  (`setSelectedId`) и кратко подсвечивать (pulse как `node-linktarget`). Дочернюю
  задачу — рядом с родителем (pin со смещением от его позиции) + выделить. Фокус
  наводить ПОСЛЕ пересчёта раскладки (`pendingFocusId` + эффект); глобальный
  `fitView` на этот релоад не запускать. Это же — фундамент инструмента «＋ нода на
  холсте» из Этапа 7.

## Критерии приёмки (измеримые)

Без чисел нельзя сказать «довели». Цели:

- **Первый экран читаем**: после загрузки видны различимые карточки/колонки, а не
  полоса. Никакая раскладка не уезжает в `zoom < 0.2`.
- **Поиск отзывчив**: ввод символа не вызывает релейаут; печать без фризов на 300
  нодах (целевой ~60 FPS, без видимых задержек ввода).
- **Холодная загрузка**: групповой scope с ~300 задач — цель **< 3 c** (после
  GraphQL); до GraphQL — сузить дефолт так, чтобы первый экран был **< 1.5 c**.
- **Порог перегруза**: при `issue_count > 150` показывается баннер «сузьте» с CTA.
- **GraphQL-паритет**: набор рёбер (тип + направление + store-оверлей) **идентичен**
  REST-пути на тестовом сидинге.

## Этап 11 — Kanban-доска: видимые дорожки (effort S-M, фронт)

Запрос пользователя: колоночные виды не читаются как доска — карточки «лежат» на
холсте под плавающими заголовками, неочевидно, что это лейны и что перенос между
ними меняет данные. Фикс (визуальный, поверх готового drag→PATCH):
- **K1. Видимые дорожки (lanes):** под колонками рисовать фоновые полосы на всю
  высоту холста + вертикальные разделители между ними; заголовки колонок остаются
  сверху дорожек. Дорожки следуют за pan/zoom (как `ColumnHeaders` через
  `useViewport`: left = vp.x + colX*zoom, width = COL_W*zoom). `pointer-events:none`,
  z-index ниже нод.
- **K2. Подсветка целевой дорожки при перетаскивании** карточки (accent-фон/рамка) —
  сигнал «бросишь сюда — сменится <измерение>». На drop срабатывает существующий
  kanban-PATCH.
- **K3. Подпись доски:** «Доска по: Спринт · перетащите карточку, чтобы сменить» —
  переиспользовать уже считающийся `groupDimLabel` (сейчас `ColumnHeaders` его
  игнорирует через `void dim`).
- Только для колоночных видов с ≥2 непустыми колонками; в грид-фолбэке одной колонки
  (Этап 10/P3) дорожки не нужны.

## Этап 12 — отдельный режим «Доска» (GitLab-style, импорт из GitLab) (effort L, фронт+бэк)

Решение пользователя: НЕ превращать холст в kanban. Холст и группировочные виды
оставить как просмотр; настоящую Kanban сделать ОТДЕЛЬНЫМ режимом по образцу
GitLab-доски, с импортом структуры прямо из GitLab.
- **D7. Импорт доски из GitLab.** Бэкенд `GET /api/boards?group|project` →
  `GET {base}/boards` (есть на CE 19). Каждая доска: inline `lists` (`position`,
  `label:{name,color}`), `hide_backlog_list`, `hide_closed_list`. Нормализовать в
  `{id, name, hide_backlog, hide_closed, columns:[{label, color, position}]}`. Если
  досок нет/403 — отдать пусто (фронт: фолбэк Open/Closed + ручное добавление).
- **D8. Режим «Доска».** Кнопка в топбаре → полноценная HTML-доска (колонки со
  скроллом, НЕ на ReactFlow-холсте): **Open | label-колонки (по порядку) | Closed**.
  Карточка как в GitLab (метки, ref, срок, аватар), счётчики в шапках, цвет колонки =
  цвет метки. «← Граф» назад. Если досок несколько — выбор.
- **D9. Раскладка задач по колонкам:** Closed = закрытые; label-колонка = открытые с
  этой меткой (в первую подходящую по порядку); Open = открытые без меток-списков.
  Доска грузит ВСЕ состояния (для Closed).
- **D10. Drag меняет данные** (готовые эндпоинты: `add/remove_labels` Этап 6,
  `state_event` Этап 0): в label-колонку → добавить её метку, снять метку
  колонки-источника; **scoped** (`x::*`) → снять другие метки той же группы (взаимо-
  исключение); в Closed → закрыть; в Open → переоткрыть/снять метку списка.
- **D11. Откат Этапа 11:** убрать дорожки/подсветку/подпись доски с холста; холст-
  колонки сделать ПРОСМОТРОМ (drag только двигает карточку, данные не меняет —
  вся kanban-логика в режиме «Доска»).
