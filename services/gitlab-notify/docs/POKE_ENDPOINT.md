# /api/poke — «пнуть исполнителя» (реализовано в gitlab-notify)

Ответ на `services/issue-graph/docs/BOT_POKE_SPEC.md`. Приёмный эндпоинт реализован,
покрыт тестами (20 шт.) и проверен локально по HTTP. issue-graph (клиент) не менялся.

## Контракт

```
POST {BOT_URL}/api/poke
Authorization: Bearer <poke_token>
Content-Type: application/json

{
  "gitlab_username": "alice",
  "issue": { "iid": 5, "title": "…", "web_url": "http://…", "project_path": "a/b" },
  "message": null,
  "poked_by": "Михаил Бахмутский"
}
```

- `gitlab_username` — логин исполнителя; резолвится в Matrix через `Identity` (как у дайджестов).
- `issue` — данные для текста по умолчанию.
- `message` — необязательный готовый текст. Рендерится как **plain text** (экранируется,
  переносы строк → `<br>`). Пусто/`null` → бот строит текст сам.
- `poked_by` — **необязательно**, кто пнул (имя или логин актора). Если задано — текст по
  умолчанию станет «🔔 **{poked_by}** пнул тебя по задаче …»; если нет — «🔔 Тебя пнули …».
  Экранируется. Игнорируется, если задан готовый `message`.

## Авторизация (обязательна, fail-closed)

- Заголовок `Authorization: Bearer <poke_token>`, сверка constant-time (`hmac.compare_digest`).
- **Токен не задан на боте → эндпоинт выключен (401).** Нужно задать одинаковый токен с обеих сторон.
- Где задать на боте: env **`POKE_TOKEN`** (сидится один раз) **или** админка →
  «Настройки» → **«🔔 Пинок (issue-graph)»** (чип-секрет, как у вебхука; меняется на лету).
- В issue-graph: поле «Токен бота» → слать тот же токен в заголовке.

## Ответы

| Код | Тело | Когда |
|----|------|-------|
| 200 | `{"ok":true,"delivered":true}` | доставлено |
| 401 | `{"ok":false,"reason":"…"}` | токен не задан на боте / неверный токен |
| 400 | `{"ok":false,"reason":"нужны gitlab_username и issue"}` | кривое тело |
| 422 | `{"ok":false,"reason":"user_not_mapped","detail":"…"}` | логин не сопоставлен с Matrix |
| 429 | `{"ok":false,"reason":"…"}` | анти-спам: кулдаун по задаче / лимит на человека |
| 502 | `{"ok":false,"reason":"ошибка доставки: …"}` | не удалось доставить (напр. несуществующий юзер) |
| 503 | `{"ok":false,"reason":"…"}` | бот выключен (kill-switch) / предохранитель сорван |

`reason` человекочитаемый — issue-graph может показывать его пользователю.

## Поведение

- DM **напрямую**, в обход мьюта, **без фоллбэка в общую комнату** (пинок личный — не утекает в чат).
- Контент **экранируется** (XSS-safe): заголовок/ссылка issue и custom `message`.
- Текст по умолчанию: `🔔 Тебя пнули по задаче #{iid} {title}` + ссылка `web_url`.
- Каждый пинок пишется в «Логи» (kind = `poke`).

## Рейт-лимиты / анти-спам (человека не заспамят)

- **Кулдаун** на пару (исполнитель + задача): дефолт **600 с** — повтор раньше → `429`.
- **Потолок на человека**: дефолт **4 пинка / 600 с** → `429` (ниже порога предохранителя,
  поэтому легитимные пинки его не срывают).
- **Глобальный предохранитель**: настоящий флуд по многим людям срывает бот + алерт инженеру.
- Всё настраивается: админка → «Настройки» → «🔔 Пинок».

## Нюанс резолва (`matrix_domain`)

При заданном `matrix_domain` (у нас `fakspro.ru`) любой логин резолвится в `@логин:домен`,
поэтому `422 user_not_mapped` практически не возникает: реальные исполнители доходят, а
несуществующий логин упрётся в ошибку доставки (`502`), а не в `422`.
